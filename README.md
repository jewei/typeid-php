# TypeID PHP

A PHP 8.4 implementation of [TypeID specification 0.3.0](https://github.com/jetify-com/typeid/tree/main/spec).

A TypeID combines a type prefix with a UUID encoded as a 26-character lowercase base32 suffix. IDs generated by this package use UUIDv7. IDs with the same prefix therefore sort by generation time.

## What it provides

- The prefix remains visible in strings, logs, and URLs. A caller can compare it with the expected record type before using the ID.
- Generated IDs use UUIDv7 and sort by generation time when their prefixes match.
- The suffix uses 26 characters instead of the 36 characters in a hyphenated UUID.
- Canonical TypeID strings use lowercase ASCII letters, digits, and underscores. They need no URL encoding.
- The codec uses PHP bit operations. It does not require GMP or bcmath.

## Requirements

- PHP 8.4 or newer

## Installation

```bash
composer require jewei/typeid-php
```

## Usage

```php
use TypeID\TypeID;

// Generate a TypeID backed by UUIDv7.
$id = TypeID::generate('user');
echo $id;           // user_01jsnsf2g7e2saxdjvz3j6tc3x
echo $id->prefix;   // user
echo $id->suffix;   // 01jsnsf2g7e2saxdjvz3j6tc3x
echo $id->toUuid(); // 01966b97-8a07-70b2-aeb6-5bf8e46d307d

// Parse a canonical TypeID string.
$id = TypeID::fromString('user_01jsnsf2g7e2saxdjvz3j6tc3x');
echo $id->prefix; // user

// Encode an existing UUID.
$id = TypeID::fromUuid('01966b97-8a07-70b2-aeb6-5bf8e46d307d', 'invoice');
echo $id; // invoice_01jsnsf2g7e2saxdjvz3j6tc3x

// Use the nil UUID as a sentinel.
$zero = TypeID::zero('user');
echo $zero->isZero();    // true
echo $zero->isNonZero(); // false

// Compare the complete value, including its prefix.
$a = TypeID::fromString('user_01jsnsf2g7e2saxdjvz3j6tc3x');
$b = TypeID::fromString('user_01jsnsf2g7e2saxdjvz3j6tc3x');
echo $a->equals($b); // true

// Store the UUID in a binary(16) database column.
$uuidBytes = TypeID::generate('user')->bytes();
$binaryId = TypeID::fromBytes($uuidBytes, 'user');
$uuidBytes = $binaryId->bytes();

// JSON uses the canonical TypeID string.
echo json_encode(['id' => $id]); // {"id":"invoice_01jsnsf2g7e2saxdjvz3j6tc3x"}

// Native serialization revalidates the value when it is restored.
$restored = unserialize(serialize($id));

// Match the nil suffix directly when necessary.
echo TypeID::ZERO_SUFFIX; // 00000000000000000000000000
```

## Public interface

| Member | Returns | Notes |
| ------ | ------- | ----- |
| `TypeID::generate(?string $prefix)` | `TypeID` | Generates a UUIDv7. This is the only constructor that creates K-sortable IDs. |
| `TypeID::fromString(string $value)` | `TypeID` | Parses a canonical TypeID string or a bare suffix. |
| `TypeID::fromUuid(string $uuid, ?string $prefix)` | `TypeID` | Accepts any valid UUID version. |
| `TypeID::fromBytes(string $bytes, ?string $prefix)` | `TypeID` | Accepts exactly 16 raw bytes. |
| `TypeID::zero(?string $prefix)` | `TypeID` | Creates a sentinel backed by the nil UUID. |
| `->prefix`, `->suffix` | `string` | Readonly properties. |
| `->toString()`, `(string)`, `->jsonSerialize()` | `string` | Return the canonical TypeID string. |
| `->toUuid()` | `string` | Returns a lowercase, hyphenated UUID. |
| `->bytes()` | `string` | Returns 16 raw UUID bytes. |
| `->isZero()`, `->isNonZero()` | `bool` | Check whether the suffix encodes the nil UUID. |
| `->equals(TypeID $other)` | `bool` | Compares both the prefix and suffix. |
| `TypeID::ZERO_SUFFIX` | `string` | The 26-character suffix for the nil UUID. |

Compare a prefix through its readonly property:

```php
$id->prefix === 'user';
```

The package uses `ramsey/uuid` to generate UUIDv7 values. It implements TypeID encoding and decoding locally.

`fromUuid()` accepts hyphenated UUIDs and bare 32-character hexadecimal UUIDs in either case. `toUuid()` returns lowercase hyphenated text. Uppercase and bare input therefore return in a different textual form, though the UUID value remains the same.

`zero()` creates a sentinel, not a generated ID. Its nil UUID has no version or variant bits. A zero TypeID is not UUIDv7 and does not provide chronological ordering. The same rule applies to non-v7 UUIDs passed to `fromUuid()`.

Invalid caller input throws `TypeID\Exception\ValidationException`, a subclass of `InvalidArgumentException`. UUID generation failures throw `TypeID\Exception\GenerationException`, a subclass of `RuntimeException`. Both implement `TypeID\Exception\TypeIDException`.

```php
use TypeID\Exception\TypeIDException;

try {
    $id = TypeID::fromString($input);
} catch (TypeIDException $exception) {
    // Handles every exception defined by this package.
}
```

## Compatibility policy

`TypeID` is the only supported production module. The table below lists the interface covered by the package's compatibility promise within a major version.

| Element | Status |
| --- | --- |
| `TypeID` factories and instance methods | Supported |
| `TypeID::$prefix`, `TypeID::$suffix`, `TypeID::ZERO_SUFFIX` | Supported |
| `new TypeID($prefix, $suffix)` | Supported. It validates both arguments. |
| `Stringable` and `JsonSerializable` behavior | Supported |
| `TypeIDException`, `ValidationException`, `GenerationException` | Supported catch contracts |
| Exception message text | Unsupported and subject to change |
| `ValidationException` named constructors | Internal |
| Native `serialize()` and `unserialize()` | Supported for runtime round trips within a major version |
| `TypeID\Base32` | Internal and subject to removal |

Native PHP serialization is not a storage format. Persist the canonical string and restore it with `TypeID::fromString()`:

```php
$stored = (string) $typeId;
$restored = TypeID::fromString($stored);
```

PHP has no package-private visibility for top-level classes, so Composer can autoload `Base32` even though it is internal. Code that calls it directly has no compatibility guarantee. `composer test:architecture` prevents production code and contract tests in this repository from depending on it.

[CONTEXT.md](CONTEXT.md) defines the domain terms used by this package, including prefix, suffix, canonical suffix, zero TypeID, nil UUID, and spec vector.

## Format

```text
user_01jsnsf2g7e2saxdjvz3j6tc3x
^^^^  ^^^^^^^^^^^^^^^^^^^^^^^^^^
|     +-- 26-character base32 suffix encoding a 128-bit UUID
+-------- type prefix
```

An underscore separates a non-empty prefix from the suffix. A TypeID without a prefix contains only the 26-character suffix. The last underscore is the separator, so prefixes may contain underscores.

### Prefix

A prefix must match `^([a-z]([a-z_]{0,61}[a-z])?)?$`.

- It contains 0 to 63 characters. An empty prefix is valid.
- It may contain lowercase ASCII letters and underscores.
- It must start and end with a letter when non-empty.
- It may contain consecutive underscores.
- It may not contain digits or uppercase letters.

For example, `my__type` is valid. `_user`, `user_`, `user1`, and `User` are invalid.

### Suffix

A canonical suffix must match `^[0-7][0123456789abcdefghjkmnpqrstvwxyz]{25}$`.

- It contains exactly 26 lowercase base32 characters.
- Its alphabet omits `i`, `l`, `o`, and `u`.
- It contains no hyphens or padding.
- Its first character cannot exceed `7`.

Twenty-six base32 characters can hold 130 bits, but a UUID contains 128 bits. The encoder prepends two zero bits. A suffix greater than `7zzzzzzzzzzzzzzzzzzzzzzzzz` would overflow 128 bits, so the parser rejects it.

### Length

A canonical TypeID string contains 26 to 90 characters. The maximum consists of a 63-character prefix, one separator, and a 26-character suffix.

## Specification conformance

The repository vendors specification 0.3.0 and its test vectors in [`spec/`](spec/). These files match [`jetify-com/typeid`](https://github.com/jetify-com/typeid/tree/main/spec) byte for byte.

The test suite runs all 9 valid and 21 invalid vectors. It also checks requirements that the vectors do not cover:

- 5,000 generated IDs survive string, UUID, and byte round trips.
- 5,000 generated IDs contain the required UUIDv7 version and variant bits.
- 5,000 generated IDs with one prefix remain in generation order when sorted.
- The codec uses the specified alphabet and maps the maximum suffix to the maximum 128-bit UUID.
- Canonical strings obey the 26-character and 90-character length limits.

## Testing

```bash
composer test              # Run the architecture check and test suite.
composer test:unit         # Run the test suite.
composer test:architecture # Check the dependency allow-list.
```

The tests have separate jobs:

| Directory | Purpose |
| --- | --- |
| `tests/Contract/` | Tests the supported interface through `TypeID` only. |
| `tests/Spec/` | Tests the vendored specification and requirements outside its vectors. |
| `tests/Codec/` | Diagnoses individual base32 bit positions through `Base32`. |

`tests/Codec/` is the only test directory allowed to call `Base32`. The codec uses 26 explicit bit expressions. Direct codec tests identify the failed byte and character instead of reporting a generic UUID round-trip failure. `composer test:architecture` rejects direct `Base32` calls from every other test directory.
